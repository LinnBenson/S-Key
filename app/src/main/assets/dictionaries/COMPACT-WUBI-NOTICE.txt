COMPACT WUBI86 DATA: PROVENANCE AND PRIVATE-TESTING RESTRICTION

This asset combines the app's original Rime Wubi86 table with five plain-data
supplements from xianghongai/rime-wubi-dict and eight explicitly requested local
built-in word/code pairs. It does not import or execute any
Rime schema, history-encoding, user dictionary, or learning configuration.
No learned input or frequency data is added.

Reproducible transformation:
- Strict UTF-8 tab-delimited rows are read after the standalone header terminator.
- Source rows are read in the complete order above: baseline, local high-priority,
  IT, administrative divisions, words, historical-cultural cities, then idioms.
- Exact (text, code) duplicates are removed, first occurrence wins. Different
  codes for the same text are retained; no frequency/rare-character filtering.
- Baseline effective weights preserve the existing engine's stable descending
  order. The one upstream non-integer weight, χ/zzxx/450.5, remains effective
  weight zero, matching the previous Kotlin toLongOrNull() fallback.
- Supplements have weight zero. No additional frequency is inferred.
- All rows of sources marked exact_priority=true are prioritized during offline
  generation in their complete-code exact groups, in priority-source/file order.
  The current eight are four-letter codes. Future valid 1-4-letter complete codes
  use the same generic rule. Same-code priority rows retain file order, and an
  already-retained ordinary-source duplicate can still receive priority.
- Static weight descending remains the primary ordinary ordering key; equal
  weights follow current source order, then row order within each source.
  Exact-only promotion preserves other candidates' relative ordinary order.
  Prefix references are selected before exact groups are promoted. Equal-weight
  proper-prefix candidates can change when source order changes; promotion alone
  does not affect prefix selection. There is no runtime special-case word map.
  Existing user exact matches still follow the first built-in candidate, and the
  final Extension B tail rule is unchanged.
- Every exact-code row is retained. Proper-prefix completion stores the first
  30 rows in current stable weight/source/row order, preserving the limit.
- Stored bytes are deterministic, big-endian SKWB0001; source strings are not
  normalized. The query engine can access indexed bytes without allocating all
  dictionary strings at startup.
