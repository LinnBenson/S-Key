ENGINE EVALUATION
Official librime is a mature BSD-3-Clause C++ input-method engine supporting
shape and phonetic input, schema processing and spelling algebra:
https://github.com/rime/librime
Official build dependencies include C++17, Boost, LevelDB, marisa, OpenCC and
yaml-cpp. Its README lists Trime and other community Android frontends.
The official Wubi mixed schema uses the same Wubi86 and pinyin_simp dictionaries:
https://github.com/rime/rime-wubi/blob/master/wubi_pinyin.schema.yaml

This application does NOT embed librime or claim librime compatibility. It
uses a smaller, independently implemented Kotlin static dictionary engine.
Rationale: no native ABI/JNI/dependency chain, no user dictionary or log store,
read-only packaged data, deterministic ranking, and auditable offline behavior.
Do not import an upstream schema wholesale: upstream mixed schema enables user
history encoding. This app deliberately has no learning or history facility.

Lookup order: exact Wubi, exact Pinyin, enabled fuzzy Pinyin, bounded static
phrase/syllable segmentation fallback, Wubi prefix completions. Duplicates are
removed by display text. Fuzzy pairs: z/zh, c/ch, s/sh, n/l, f/h, an/ang, en/eng,
in/ing. Fuzzy uses a shared canonical key (not neural autocorrect); concatenated
spellings can have extra collisions. Apostrophes/spaces preserve explicit
syllable boundaries. Phrase decoding is bounded beam search over the static
lexicon; it is not a contextual language model and may rank unusual phrases.
English is a small hand-selected current-word completion list, no next-word
prediction. No learning API, personal frequency file, sync or network path.

COMPACT WUBI RUNTIME AND REQUESTED SUPPLEMENTS (2026-10-12)

Runtime Wubi lookup uses compact-wubi.skwb, a deterministic read-only binary
index over the unchanged baseline plus five user-requested Wubi86 supplements
and a separately pinned wubi86_high_priority.dict.yaml source with eight explicit
built-in word/code pairs, marked exact_priority=true in the source manifest.
All 441,796 unique (text, code) rows are retained, including rare characters;
only exact duplicates are removed. Full four-code matches remain reachable
beyond a 40-item UI page. During offline index generation only, marked priority
source rows lead their complete-code exact groups in source/file order. All other
exact candidates retain their relative ordinary order. Static weight descending
remains first; equal-weight ties follow baseline, local high-priority, IT,
administrative divisions, words, historical-cultural cities, then idioms, and
row order within each source. Proper-prefix candidates use this same ordinary
order before exact-only promotion; equal-weight prefix order may change with
source order. Priority also applies to a marked pair already retained from an
ordinary source. No word
map or extra ranking branch is added to the runtime engine. The existing user
exact-match second-position rule, exact-text deduplication and Extension B tail
rule remain unchanged. The APK stores this asset uncompressed for direct mapping;
words are decoded on demand and are not all retained as heap objects. There is
no query cache, input history, user-frequency learning, or mutable content in
this mapping. The separate manually edited user dictionary stays separate.

See COMPACT-WUBI-NOTICE.txt for precise source attribution, pinned hashes,
transformation details and the supplement licensing caveat. The supplement
repository supplies no LICENSE, so these additions are restricted to the
requested private test build pending permission review for redistribution.
The original LGPL baseline and its source/license files remain unchanged.
Rebuild tools, all six original inputs and the local source are included in the
source package. The local pairs are preserved exactly as supplied and survive
clearing mutable user content. To maintain priority words, edit the independent
high-priority source, re-pin its metadata, then rebuild the compact index; there
is no second manually maintained word/code priority map.
