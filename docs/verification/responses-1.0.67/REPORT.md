# 1.0.67 Responses 多轮会话验证

日期：2026-10-19（Asia/Singapore）。

## 行为

- 原文生成/重新生成始终新建会话，POST /responses，不携带 previous_response_id。
- 补充要求及快捷提示仅发送一个新 user 消息和当前结果的响应 ID，不重复发送原文、旧回答、任务提示词或 instructions。
- 首次生成使用 system 消息保存任务规则；自定义模式的 system 内容仅为用户提示词。
- 响应 ID 绑定原文内容、编辑代数、接口、模型及密钥指纹。原文修改（即使改回原值）后旧 ID 不能续聊；必须重新生成。
- 同一份未修改的原文可以切回历史结果并从所选响应分支续聊。最多保留 8 个本机结果，退出清除。
- 流式解析仅在 response.completed、completed 状态、有效 ID 和非空正文全部满足时确认成功。失败、截断、取消、超限和仅 [DONE] 均不产生可续聊 ID。忽略推理片段，不向用户展示原始服务端错误。
- 提交按钮采用官方 Miuix Regular Send 图标，尺寸与 12sp 文字一致，间距 5dp；布局为补充输入框、快捷提示、Send＋提交。

18 项设备回归覆盖流式事件、Unicode/换行、无重复末帧、取消、上下文 ID、模拟 HTTPS 请求体、过期 ID 不回退、来源变化、原文生成全新会话、多轮与历史分支，以及先前的候选展开修复。使用合成原文和模拟连接，不读取真实密钥、不调用真实云端。

未验证真实账号、真实模型/代理服务兼容性及长时间真机负载；不宣称通过真实云端端到端测试。

## 1.0.68 回车焦点修正

原文框回车生成新会话；补充框回车提交新要求并携带当前响应 ID。空补充要求只提示，不触发原文生成；有中文编码时先确认输入，生成中回车仍停止。覆盖安装 1.0.68 后，会话请求体、补充草稿和展开候选的 3 项设备回归均通过。
