# 自动空格与预览替换延迟修复（2026-10-24）

## 问题与处理

1.1.10 的自动空格路径先清除预编辑区间，再把上屏任务交给与候选查询共用的工作线程。读取宿主上下文期间，后续按键排队，光标会先退回预编辑起点，再随最终文字向前移动。

本次移除自动空格提交队列。候选确认直接通过 commitText 替换预编辑区间，不再先 setComposingText(空字符串)。需要在后缀空格前放置光标时，与文字替换放在同一个 batch edit 中完成。候选查询不等待自动空格预读。

SpacingContext 在独立的单线程、仅保留最新请求的邮箱中预读前后各两个字符。结果检查编辑器、选区、预编辑修订和生命周期；实际提交后更新短上下文，切换宿主、外部移动光标、结束输入或关闭功能时失效。销毁时关闭邮箱与线程。密码、邮箱、网址和非文本字段不预读。

上下文未及时返回时，仍立即提交，只处理本次文本内部可确定的空格，不猜测外部边界、不在稍后补改已提交文字。这意味着慢宿主或极快的首次输入可能跳过外部边界空格；没有为保留这些空格重新引入主线程读取或延迟提交。
