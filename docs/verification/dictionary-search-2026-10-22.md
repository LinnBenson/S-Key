# 词库查询优化（2026-10-22）

基于 1.0.78 发布后的代码。本次改动尚未包含在已发布的 1.0.78 安装包中。

后续高优先级词库改动调整了拼音精确排序与默认缓存版本，见[对应记录](pinyin-prediction-priority-2026-10-22.md)。下文为本轮查询优化完成时的测量。

## 改动

检查了五笔精确/前缀、拼音精确/模糊/音节/联想、拼音首字母、英文补全和中英文自定义词库查询。

五笔精确排序、模糊拼音索引及纯拼音组句算法保持原有行为。主要优化了以下路径：

1. 编译时为五笔、英文的 1–2 字母前缀预先保存排名，输入时直接读取。五笔仍最多返回 30 个前缀候选；英文常用请求最多 12 个，超过 12 个时使用完整查询，不截断请求。
2. 拼音、混输及首字母精确查询不再使用含五笔优先级的排序索引，避免额外排序。新索引仅覆盖这三类数据。
3. 拼音联想原来已经可以使用去重索引定位文字范围；本次增加覆盖索引，只读取所需文字，不再读取编码、权重并构造 Entry。
4. 中英文自定义词库在已有快照上增加编码索引，查询只筛选相关前缀，再按用户原有顺序合并。纯拼音组句仍使用完整自定义词条列表。

不缓存查询历史，不上传词条。SQLite 页缓存仍为约 2 MiB；新增索引位于磁盘，不会在启动时全部转成 Kotlin 对象。默认运行库从 92,577,792 字节增至 101,388,288 字节，增加约 8.4 MiB。自定义索引随现有快照失效，不保留旧版本。

默认运行库缓存升级到 runtime-v5.db，SQLite schema 版本为 3。旧编译库仍兼容，需要重新编译才使用新索引；不自动应用用户草稿。

## 验证

- 235 项 JVM 测试通过，包括自定义编码归一化、大小写、保存顺序、无匹配以及 10,000 条候选不截断。
- 41 项 Python 测试通过，包括全部五笔精确顺序、所有已生成短前缀的排名一致性、索引查询计划及词库完整性。
- 70 项 BlueStacks 设备测试通过：内置词库 12 项、ContentStore 31 项、双语内容存储 16 项、候选交互 11 项。
- 手机端完整默认编译与随包编译结果一致；旧 schema 查询、超过预计算上限的英文查询、编辑/删除后即时失效均通过。
- 候选交互覆盖纯拼音组句和分段、混输隔离、自定义词条、英文空格选词以及过期候选拒绝。
- Debug 与设备测试 APK 构建通过；隐私检查、git diff --check 通过。

第一次 Python 测试与 Gradle 词库重建同时读取同一生成目录，出现一次目录尚未填充的失败；待生成完成后完整重跑，41 项通过。后续复现时应先完成构建，再执行词库测试。

## 查询耗时

在开发机 SQLite 中比较同一份默认词库；预热 5 次后测 40 次，取中位数。旧库来自本次修改前，新库由新编译脚本生成；样本的候选文字顺序逐一比对一致。这是 SQL 查询测量，不代表 Android 整体按键延迟，也不是冷启动或磁盘峰值测试。

| 查询 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 五笔前缀 a，30 条 | 1.3126 ms | 0.0172 ms |
| 英文前缀 s，12 条 | 2.8127 ms | 0.0103 ms |
| 拼音 ni，64 条 | 0.0365 ms | 0.0331 ms |
| 首字母 y，全部候选 | 0.5902 ms | 0.4646 ms |
| 拼音联想“中国”，12 条 | 0.0290 ms | 0.0194 ms |

复现：

```sh
./gradlew testDebugUnitTest assembleDebug assembleDebugAndroidTest
python3 -m unittest discover -s tests -p 'test_*.py'
python3 tests/benchmark_dictionary_search.py --before /path/to/old-runtime.db --after app/build/generated/dictionaryCatalog/dictionaries/runtime.db
python3 tests/privacy_audit.py
```

真实设备上的耗时、存储和内存变化仍需实测。本次未修改词库编辑器的全文搜索，也未把性能优化等同于拼音组句准确率提升。
