# 三种中文输入模式与词库源文件校验

## 行为

- 历史工作先保存为提交 `83b3afd`；本次输入模式修改在其后进行。
- 输入方式顶部提供五笔、五笔拼音混输、拼音输入。缺省或未知配置回退混输。
- 更多工具及可定制工具栏提供“输入模式”，按五笔 → 混输 → 拼音循环；图标为五/混/拼。原有工具栏固定项保持不变。
- 五笔/混输空格显示“ 五笔 ”，纯拼音显示“ 拼音 ”；三种模式沿用中文符号页及中文自定义词库。
- 纯五笔只查询五笔；混输保留现有排序；纯拼音使用内置 `pinyin_simp.dict.yaml` 编译后的独立 pinyin 索引，不查询五笔，也不触发四码自动上屏。
- 拼音采用有界词图与 beam 搜索组句。全句候选之后列出可分段选择的前缀词；已选部分保留在键盘预编辑区，最后一段确认才整句提交。退格删除剩余拼音，删空时可退回上一已选段。回车沿用输入原始剩余编码的行为。
- 上下文来自当前输入框光标前最多 16 个字符（助手编辑时来自助手草稿），在本地词组前缀索引中预测、参与组句排序；整句上屏后展示后续候选。密码输入框不查询。上下文、组句缓存不写盘，不发送网络，结束输入即释放。
- 最多 128 个原始拼音字符（含已选段）；查询使用局部缓存、有界数据库查询和 beam 宽度，避免每次加载整个拼音库。

## 质量边界

这是本地词频和词组关联驱动的实现，支持整句、分段及上下文预测三个流程；不是神经语言模型，也未宣称与主流输入法的纠错、缩写输入、个性化学习或长句首选准确率等同。现有拼音词库约 6.5 万条，词库覆盖和词频仍会影响候选质量。

## 词库校验

导入、保存修改、改变文件扩展名时先检查全部源文件，成功才发布草稿；不合格内容不会覆盖旧源文件。编译时再次解析，失败不替换活动快照。

- UTF-8、64 MiB 文件上限、8192 字符单行上限。
- Rime YAML 要求 `name` 和 `...`；列顺序只能为 text/code/可选 weight，兼容原版五笔额外 stem 列；拒绝未实现的 import_tables。
- 中文 TSV 为文字、编码、可选词频；英文 TSV 为小写单词和正整数词频；不忽略多余列。
- 五笔编码 1–4 个小写字母；拼音必须为空格分隔的合法音节；拒绝负数、非法词频、错误分隔符及无有效词条的导入/保存。
- 新建文件允许空模板，以便随后编辑；空模板不能编译，须填入词条或删除。原版五笔唯一的历史小数词频兼容规则仍保留。

## 后续增量：混输限定拼音源与单字母词库

- 混输的拼音来源仅为文件名 `pinyin_simp.dict.yaml`，五笔来源保持不变；其他内置拼音文件只用于纯拼音。中文自定义词库仍即时生效。
- 编译快照 v2 为混输保留单独的 `mixed_pinyin` 命名空间（包括独立模糊/音节索引）。同词条在其他文件出现或具有不同词频，不会污染混输索引。删除基础文件后重新编译，混输不再产生该文件的拼音候选。
- 新增 `pinyin_initials.dict.yaml`：26 个字母、78 个默认候选，`n → 你/那/能`、`w → 我/为/问`。i/u/v 为人工配置快捷键位；用户可编辑，编码必须是一个小写字母。
- 单字母文件编译到 `pinyin_initial`，只在纯拼音查询恰好一个字母时读取，不参加连续全拼的词图拆分；中文自定义的同编码词条优先。
- 文件名用于决定上述用途，列表显示“混输与纯拼音共用”/“仅纯拼音使用”。改名后按新文件名在下一次编译时决定用途。
- 升级时只向旧草稿补一次新文件，保留已有文件内容；用户随后删除它不会被自动重新添加。增加文件后仍须编译。工厂运行库更新为 runtime-v3、目录元数据为 defaults-v6，旧副本在无读者时清理。
- 旧编译快照未保留文件来源，不能可靠分离其已合并词条。因此重新编译前，混输临时使用随包的基础拼音库，旧快照继续提供五笔和纯拼音；不会偷偷编译未应用的草稿，也不会让旧快照额外词库泄漏到混输。重新编译后使用用户当前基础文件内容。
